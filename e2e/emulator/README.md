# Эмулятор инсталляции

Порт RS-485 с WB-DALI, его шинами DALI и соседями по линии — по профилю инсталляции. Настоящий
wb-mqtt-serial работает с эмулятором вместо реального порта. Используют `e2e/large_installation`
и `e2e/bus_saturation`; каждый e2e держит свои профили в своём `profiles/`.

## Устройство

`emulator.py`, один процесс на asyncio. Работает весь прогон e2e и хранит состояние между
итерациями, в том числе старые значения регистров ответов. Вывод — `/run/e2e-emulator/emulator.log`.

- **Линия RS-485** — Modbus RTU slave на pty, slave-сторона — `/run/e2e-emulator/ttyEmulator`.
  Ответ уходит не раньше, чем дошёл бы по проводу на скорости порта из профиля, плюс 0,23 мс +
  8 символов от конца запроса. События fast Modbus (0x46) — с паузой арбитража.
- **WB-DALI** — регистры шаблона `config-wb-dali.json` плюс очередь, указатель и ответы каждой
  шины. Размер очереди и адреса — из `WBDALIConfig` драйвера, адреса ответов (1500+) — в эмуляторе.
  - Запись указателя во время кадра оставляет записанный указатель, перезапись слота — новую
    команду.
  - Код размера кадра в слоте: 0 — FF16, 1 — FF24, 2 — FF25, 3 — FF17 (17-битный кадр Helvar,
    17-й бит — младший бит данных слота). FF17 шлюз отправляет с прошивки 1.3.0, более старая
    код 3 отправляет как FF16.
  - Время кадра (`TimingProfile`): прямой 15,8 мс (24-битный 22,5 мс, 17-битный — 16-битный плюс
    один бит DALI, 0,83 мс); задержка обратного 7 мс, обратный 9,2 мс, без ответа 10,5 мс; пауза
    перед прямым по приоритетам 1..5 — 13,5, 14,9, 16,3, 17,9, 19,5 мс; `sendtwice` — двойной.
  - Прошивка 1.3.0, сигнатура `dali3G15`. Fast Modbus: включение событий и чтение с
    подтверждением, без события перезагрузки.
  - События в пачку берутся как у WB-DALI: по приоритету, затем input раньше holding, затем по
    возрастанию адреса, без учёта того, когда событие произошло. Пока у регистров ответов шины 1
    есть новые события, ответы шин 2 и 3 ждут следующих чтений. Discrete и coil идут после
    holding — на железе это не проверялось.
- **DALI-устройства** — `dali.tests.fakes.Gear` с ответами на запросы инициализации и опроса
  wb-mqtt-dali и на QUERY SHORT ADDRESS при поиске; RANDOMISE gear принимает только после
  INITIALISE, как настоящий, и свой фейк control device (random address, поиск и адресация, instances).
  Одновременный ответ нескольких устройств даёт битый обратный кадр. 17-битный кадр получают
  только модели Helvar, слово — данные без младшего бита; остальные устройства его игнорируют.
- **Соседи** — регистры по шаблону wb-mqtt-serial (объекты с `address`, без `reg_type` — holding)
  плюс служебные регистры WB. Из нескольких шаблонов одного `device_type` берётся тот же, что у
  wb-mqtt-serial: последний по отсортированному пути.

## Профиль

Каталог из трёх файлов:

| Файл | Что берётся |
| --- | --- |
| `wb-mqtt-serial.conf` | порт с единственным `WB-DALI`: скорость линии, slave id шлюза, соседи (`device_type`, slave id) |
| `wb-mqtt-dali.conf` | шины `wb-dali_<slave id>`: адреса, random address, `dali2: true` — control device; имена эмулятору безразличны |
| `devices-state.json` | шина (с 1) → `gear`: адрес → `{"model": ..., "groups": [...], "firmware": ...}`, `control_devices`: адрес → `{"model": ..., "instance_types": [...]}` |

```json
{"1": {"gear": {"0": {"model": "OTI DALI 15/220-240/1A0 NFC", "groups": [3, 4]},
                "6": {"model": "Helvar 311", "firmware": "5.12"}, "8": {"model": "Helvar 321"}},
       "control_devices": {"0": {"instance_types": [1, 2, 3, 4]}, "10": {"model": "Helvar 321"}}}}
```

У каждого gear из `wb-mqtt-dali.conf` должна быть запись с `model`; `groups` по умолчанию пустые.
`firmware` — только у моделей Helvar: строка `"старший.младший"` с двумя цифрами младшего номера,
ответы на Extended Query Major / Minor Version; без неё — версия модели. Control device без записи
— с instances `[1]` и GTIN фейка python-dali; `model` задаёт GTIN банка 0 и instances по умолчанию,
`instance_types` их заменяет. Gear без записи или без `model`, неизвестная модель, лишний ключ,
`firmware` не той формы или не у модели Helvar, запись об устройстве или шине, которых нет в
`wb-mqtt-dali.conf`, — ошибка при загрузке профиля.

Модели gear (`model`):

| Модель | Что эмулируется |
| --- | --- |
| OTI DALI 15/220-240/1A0 NFC | GTIN, device types 6, 50, 51, 52, банки 1, 202, 205–207, DT6 |
| BK-DCL010S-AHA0700ADN | GTIN; на QUERY DEVICE TYPE отвечает 254 — только общие команды части 102, без настроек LED и энергии. Упрощение: по `products.csv` у продукта DT6 и банки 251–253 |
| DC MINI JOLLY DALI BI | GTIN; на QUERY DEVICE TYPE отвечает 254, как BK-DCL010S-AHA0700ADN. Упрощение: по `products.csv` у продукта DT6 и банк 251 |
| Helvar 311 | датчик Digidim без GTIN в банке 0: участвует в поиске и отвечает на QUERY SHORT ADDRESS, из адресных команд FF16 — только на QUERY CONTROL GEAR. Команды Helvar FF17 на свой короткий адрес: `E5`/`E6` — версия (по умолчанию 6.08), `9A` Read E2 — байт E2 по адресу из DTR0 (FF16 `A3 xx`), адрес +1; `84` Enable Write E2 разрешает один следующий кадр `C3 xx` Write E2, тоже с адресом +1; `C5 xx` Extended DTR MSB принимается и ничего не меняет. E2 — дамп живого 311 (GTIN 5030797003118), серийный номер (байты 7–9) — random address |
| Helvar 312 | модель Digidim, которую wb-mqtt-dali не поддерживает: как Helvar 311, но версия 6.47 и в E2 GTIN 5030797003125 |
| Helvar 321 | как Helvar 311, но версия 10.41, в E2 GTIN 5030797003217 и заводские значения 0x10–0x2F датчиков 32x. Его часть DALI-2 — отдельный control device с `model: Helvar 321` и тем же random address в `wb-mqtt-dali.conf` |
| default_gear | без GTIN; на QUERY DEVICE TYPE отвечает 254 — простой светильник части 102: яркость, группы, сцены, фейд, без настроек типа устройства |

Модели control device (`model`):

| Модель | Что эмулируется |
| --- | --- |
| Helvar 321 | GTIN 5030797003217 в банке 0, instances 303 и 304 (`[3, 4]`) |

## Подготовка эмулятора

Перед прогоном e2e:
1. Сохраняет `/etc/wb-mqtt-serial.conf` (и конфиги, которые меняет сам e2e) в `*.e2e_emulator.bak`
   и запоминает, какие сервисы были запущены. Если бэкап остался от прерванного прогона, не
   стартует: верните его (`mv …bak …conf`) или удалите.
2. Останавливает сервисы и запускает эмулятор.
3. Пишет конфиг wb-mqtt-serial: порт шлюза из профиля, у которого заменён только `path`.

После прогона, в том числе при ошибке и Ctrl-C: останавливает сервисы, затем эмулятор, возвращает
конфиги и исходное состояние сервисов. С `--keep-emulator` ничего не разбирается: эмулятор
остаётся работать, скрипт печатает его PID, бэкапы остаются.
