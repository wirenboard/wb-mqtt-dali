# Картинки DALI-устройств

Картинка на устройство: файл `<gtin без ведущих нулей>.webp`, не больше 960 px по длинной
стороне.

`registry.json` — реестр всех GTIN, с которыми уже разобрались. По нему определяется, какие
устройства новые. На каждый GTIN пишется статус:
- `picture` — картинка есть;
- `not_found` — искали, не нашли;
- `discontinued` — снято с производства;
- `no_picture` — картинки нет с первой сборки, причина не записана.

## Сценарий для новых устройств

Скрипты лежат в `scripts/`: `pictures.py` (команды `find`, `check`, `normalize`), `review.py`
(страница оценки) и промпт субагента `AGENT.md`. Рабочие данные поиска лежат в `new/`. Все
команды запускаются из папки `dali_pictures`.
Нужны numpy, pillow и scipy, один раз:
`python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`, дальше работать в
активированном `.venv` (`. .venv/bin/activate`), тогда `python3` в командах и у субагента
найдёт их.

1. В wb-mqtt-dali `scripts/dali_products_harvester.py` обновляет `products.csv` по реестру DALI
   Alliance. Списка новых он не отдаёт, новые просто дописываются в конец файла.
2. `python3 scripts/pictures.py find <wb-mqtt-dali>/products.csv` ставит в очередь GTIN, которых нет в
   `registry.json` и для которых нет законченного поиска. Поиски с итогом `not_found` и
   `discontinued` при этом дописываются в `registry.json`. Очередь пишется в
   `new/queue/batch_NNN.json` по 25 штук.
3. На каждый батч запускается субагент с промптом из `scripts/AGENT.md` и номером батча. Он
   скачивает и проверяет картинки через `scripts/pictures.py check`, кладёт их в `new/images/`, итоги в
   `new/results/<gtin>.json`. Когда все субагенты закончили, `python3 scripts/review.py --prepare`
   нормализует найденное на всех ядрах в кэш `new/cache/`, чтобы страница оценки открылась сразу.
4. `python3 scripts/review.py` открывает страницу оценки на порту 8790. Слева найденная
   картинка, справа результат нормализации. Можно принять (A), отклонить (X), довернуть (T),
   выключить автоповорот (B), не отбеливать светло-серый фон (W) и задать рамку обрезки с
   закраской (F).
   После каждой правки картинка нормализуется заново. Принятая сразу пишется в `new/accepted/`
   (или в каталог из `--out`) и получает в `registry.json` статус `picture`.
   Кнопка «Принять все без решения» принимает разом всё, что на вкладке (с учётом поиска) ещё
   без решения; дальше отклоняются только неудачные.
   Решения хранятся в `new/decisions.json`.
   Результат из кэша пересчитывается, только когда меняется `pictures.py`, исходная картинка
   или отметки; при запуске страница в фоне по одной досчитывает недостающие.
5. `python3 scripts/pictures.py find <wb-mqtt-dali>/products.csv --again` ставит отклонённые в очередь
   ещё раз вместе с комментарием, почему отклонили, и всё повторяется с шага 3.
6. Принятые картинки заливаются на сервер:
   ```
   s3cmd sync --acl-public --access_key=<ACCESS_KEY> --secret_key=<SECRET_KEY> \
       new/accepted/ s3://<BUCKET>/<PATH>/
   ```
   Без `--delete-removed` `sync` ничего на сервере не удаляет и грузит только новые и
   изменённые файлы, так что в `new/accepted/` можно держать лишь новые картинки. С
   `--dry-run` он только печатает, что сделал бы: там должны быть одни `upload:`. Картинку,
   принятие которой отменили после заливки, с сервера удаляют вручную через `s3cmd del`.

## Что делает нормализация

Код в `scripts/pictures.py`, функция `process_file(file, mark)`. Одна исходная картинка превращается в
одну webp. Шаги по порядку (без страницы оценки: `python3 scripts/pictures.py normalize <картинки> --out <каталог>`):

1. **Загрузка.** Картинка ставится прямо по EXIF, прозрачность заливается белым, рабочая копия
   уменьшается до 2000 px по длинной стороне.
2. **Проверка фона** по четырём углам. Белый фон, если белые хотя бы три угла. Если хотя бы
   три угла светло-серые, фон отбеливается: по серым ровным пикселям, связанным с краем
   картинки, подгоняется плавная поверхность (полином второй степени, градиент и виньетка тоже),
   и картинка делится на неё. Фон становится белым, товар светлеет в той же пропорции; белый
   корпус на сером фоне может выгореть, тогда отбеливание выключается отметкой `keep_background`
   (W на странице оценки). Флаг `whitened`. Если фона для подгонки меньше 20% (товар во весь
   кадр), отбеливания нет. Не отбелённый фон даёт флаг `background-light` (светло-серый) или
   `background`, шаги 3, 4, 5 и 6 не делаются, а картинка уходит на повторный поиск.
3. **Обрезка лишнего.** Сначала применяются ручная рамка и закраска из отметок, если они есть.
   Потом автоматически:
   - срезается тонкая рамка вокруг всей картинки (так рисует HEP), если нет ручной рамки;
   - находятся куски на картинке, товаром считаются крупные (от 15% самого большого), а
     подписи, строки текста, баннеры во всю ширину, логотипы и значки вокруг него обрезаются.
     Серые тени остаются, но светло-серый кусок с ровной заливкой (кружок «OEM») считается
     значком, если он не светлее 225: белый корпус тоже ровный. Повторяется до 5 раз, потому что подпись бывает спрятана за баннером;
   - куски внутри рамки товара, которые его не касаются (например «10W» в углу), закрашиваются
     белым. Если вокруг товара ничего лишнего не нашлось, закрашиваются только мелкие куски,
     обрезанные краем, даже светлые (кусок соседнего изделия, попавший в ручную рамку):
     надписи на белом корпусе тоже выглядят отдельными кусками.
4. **Обрезка белых полей** по порогу 12 уровней от белого.
5. **Выравнивание диагонали.** По силуэту считается главная ось. Длинный прямоугольный товар
   (длина к ширине от 2.5, заполнение рамки от 0.75), лежащий под углом 10–80°, поворачивается
   горизонтально. Отметка `rotate` поворачивает длинный товар при любом угле, `level` любой
   товар (коробку снятую под углом), `bad` выключает автоповорот.
6. **Повторная обрезка** после поворота: могли вылезти куски, которые раньше попадали в рамку.
7. **Флаги качества:** `small` (исходник меньше 200 px), `small-product` (товар меньше 400 px
   в пикселях исходника), `extreme-ratio` (стороны больше 1:8). С `small`, `small-product`,
   `background`, `background-light` картинка идёт на повторный поиск.
8. **Сохранение.** Белое поле 4% от длинной стороны, уменьшение до 960 px (не увеличивается),
   webp качества 80.

Все пороги собраны константами в начале `scripts/pictures.py`.
